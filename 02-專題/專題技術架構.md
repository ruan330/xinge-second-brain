# 專題技術架構

## 架構圖（文字版）

```
LINE 使用者
   │ webhook
   ▼
API Gateway ──► Lambda (webhook handler) ──► DynamoDB (subscriptions)
                                                   ▲
EventBridge (每分鐘) ──► Lambda (poller) ──► 公車 API ──┘
                                │
                                └──► LINE Push API ──► 使用者
```

## 為什麼用 Serverless

- 暑假在 [[AWS Cloud Practitioner 筆記]] 學到 Lambda 用多少付多少，專題流量很低，一個月幾乎免費。
- 不用管機器，[[張立群教授]] 也說專題不要花時間在維運上。

## 元件

| 元件 | 用途 | 備註 |
|---|---|---|
| API Gateway | 接 LINE webhook | HTTP API 比 REST API 便宜 |
| Lambda (Python 3.12) | 兩支：webhook handler、poller | 都掛 LabRole |
| DynamoDB | 存訂閱資料 | PK = userId, SK = stopId |
| EventBridge | 每分鐘觸發 poller | 這是推播延遲的嫌疑犯 |
| CloudWatch Logs | 看 log | |

## 已知問題

1. **推播延遲 2-3 分鐘**：EventBridge 最小是 1 分鐘，加上公車 API 本身更新頻率不明。[[2026-09-08 專題會議]] 決定先量測公車 API 的更新頻率再說。
2. **冷啟動**：第一次呼叫 Lambda 要 1 秒多，使用者會覺得 bot 反應慢。可以用 provisioned concurrency 但要錢。
3. **Learner Lab 限制**：Lambda 最多 10 個並行，正式上線要換到自己的帳號。
